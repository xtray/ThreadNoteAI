# 程序审查与修复（2026-11-12）

本次检查覆盖会话/配置/笔记状态、导入导出、IndexedDB、持久化 saga、AI 请求和流式响应、笔记编辑及扩展代理代码。基线为 25 个测试文件、113 项测试通过，生产构建通过。改动尚未提交。

## 已修复

- IndexedDB 首次打开失败后缓存被拒绝的 Promise，后续操作无法重试。失败时清理缓存。
- 数据库连接未响应 versionchange，可能阻塞其他页面升级。关闭旧连接并允许重开；旧连接延迟关闭不会使新连接失效。
- 异步初始化后，创建会话、追加消息、更新笔记仍写入旧 action 的数据，可能恢复已删除内容或覆盖新批注。保存前读取当前状态，跳过已删除对象；批量笔记保存同样读取当前状态。
- 删除轮次中的子会话后，活动会话仍指向已删除对象。现在回退到所属会话。
- 删除轮次时未清理多模型回答和标签状态，导出仍包含已删除回答。现在同步清理。
- Google SSE 将重复增量误认为累计文本，导致吞字。按增量拼接。
- 扩展端流式解析回调异常未拒绝请求 Promise，可能一直显示生成中。现在捕获异常并结束请求。
- 笔记防抖保存被切换或卸载取消，丢失最后编辑。编辑事件立即更新 Redux 并触发持久化。
- 仅打开笔记即因拆分重组压缩空行并自动覆盖原文。现在只在编辑时保存；保存回显也不会退出编辑框。
- 清空聊天数据库失败后，界面清空状态无法恢复。使用 finally 恢复状态并记录失败。

## 覆盖边界与后续风险

这不是无缺陷或完整安全认证。IndexedDB、扩展端口和笔记 hooks 主要使用模拟环境验证，未进行真实 AI 服务请求、Chrome 扩展安装及多标签页实机测试。

持久化修复覆盖初始化等待期间的过期写入；现有 takeEvery 写入未提供跨多个操作的整体事务顺序，写入已开始后发生删除的竞态仍需浏览器级验证。

扩展后台断开端口后的异常路径仍可能再次调用 postMessage；这是静态审查风险，未进行生命周期复现。

清空聊天失败目前会恢复操作状态并记录错误，但界面已清空而磁盘旧数据可能仍在，重新打开可能恢复旧历史；尚未增加用户可见的失败提示或事务式界面回滚。

`npm audit --json` 与指定官方 registry 的重试均因 DNS 解析失败而未完成，不能据此判断依赖漏洞情况。
